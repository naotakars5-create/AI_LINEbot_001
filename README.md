# AI Digest

毎朝7時に、世界中のAI関連の記事を集めて日本語に直し、LINEに5本だけ届けるしくみです。
サーバーは要りません。GitHubの上で毎朝ひとりでに動きます。

- **LINE** … 1記事1枚のカードが横に並びます。重要度・媒体・和訳タイトル・要約1行と、
  「原文」「くわしく」のボタンつき。読む／読まないをその場で判断する用
- **Webページ** … 3行要約・「何が変わったか」・専門用語の解説。腰を据えて読む用

---

## 全体の流れ

```
feeds.yaml のRSSを巡回
        ↓  新着を集める（前に送ったものは除く）
AIが「今日読む5本」を選ぶ     ← 日本語2〜3本 : 英語2〜3本
        ↓
本文を取ってきて日本語に要約
        ↓
docs/ にHTMLページを作る  →  GitHub Pagesで公開
        ↓
LINEにカードを1通送る
```

毎朝の実行は `.github/workflows/daily.yml`（GitHub Actions）が受け持ちます。
処理の中身はすべて `main.py` の中にあり、上の5段階がそのまま関数に分かれています。

---

## ファイルの役割

| ファイル | 中身 |
|---|---|
| `main.py` | 収集・選抜・和訳・ページ生成・LINE送信の本体 |
| `feeds.yaml` | 収集先のRSS一覧。ここを編集すれば取材範囲が変わる |
| `.github/workflows/daily.yml` | 毎朝7時に `main.py` を動かす設定 |
| `docs/style.css` | 公開ページの見た目 |
| `docs/index.html` | 最新版のページ（毎朝上書きされる） |
| `docs/log/YYYY-MM-DD.html` | 日付ごとの保存版 |
| `state.json` | 送信済みURLの記録。同じ記事が二度届かないようにする |

## 準備するもの

1. GitHubアカウント
2. Gemini APIキー（https://aistudio.google.com/apikey で発行。無料枠あり）
3. LINEアカウント

---

## 手順1: LINE側の準備（15分）

1. https://developers.line.biz/ja/ にLINEアカウントでログイン
2. プロバイダーを作成（名前は何でも可）
3. 「新規チャネル作成」→ **Messaging API** を選ぶ
4. **「Messaging API設定」タブ** を開く
   - QRコードが出るので、自分のスマホのLINEで読み取って**友だち追加**
   - 一番下の「チャネルアクセストークン（長期）」を **発行** してコピー
     → これが `LINE_CHANNEL_ACCESS_TOKEN`
   - 「応答メッセージ」は**オフ**にしておくと、こちらが送ったとき自動返信が来なくて静かです
5. **「チャネル基本設定」タブ** の一番下にある「あなたのユーザーID」をコピー
   → これが `LINE_USER_ID`

これで「自分だけが友だちの、自分専用アカウント」ができました。
無料枠は月200通なので、1日1通なら十分おさまります。

---

## 手順2: リポジトリの準備（10分）

1. GitHubで新しいリポジトリを作り、このフォルダの中身を全部アップロード
2. **Settings → Secrets and variables → Actions** を開く
3. 「Secrets」タブで **New repository secret** を3つ登録

   | 名前 | 中身 |
   |---|---|
   | `GEMINI_API_KEY` | Gemini APIキー |
   | `LINE_CHANNEL_ACCESS_TOKEN` | 手順1でコピーしたトークン |
   | `LINE_USER_ID` | 手順1でコピーしたユーザーID |

4. **Settings → Pages** を開く
   - Source を「Deploy from a branch」
   - Branch を `main` 、フォルダを `/docs` にして Save
   - 数分後に `https://ユーザー名.github.io/リポジトリ名/` が見られるようになります

5. さきほどの「Variables」タブに戻り、**New repository variable** を1つ登録

   | 名前 | 中身 |
   |---|---|
   | `PAGES_URL` | `https://ユーザー名.github.io/リポジトリ名` |

   （LINEに貼るリンクに使います。末尾のスラッシュは不要）

## 手順3: 動かしてみる

**Actions タブ → daily-ai-digest → Run workflow**

初回だけ手動で回して、LINEに届くか確認してください。
うまくいけば、あとは毎朝7時に勝手に動きます。

### 手元で試したいとき

```bash
pip install -r requirements.txt
export GEMINI_API_KEY="..."

python main.py --dry-run   # ページも書かず、LINEにも送らず、結果を画面に出すだけ
python main.py --no-line   # ページは作るが、LINEには送らない
```

`--dry-run` ならLINEの設定がなくても動くので、収集先を足したときの確認に使えます。

## 重要度 A・B・C の意味

記事ごとにAIが付けます。基準は `main.py` の `summarize()` の中に書いてあります。

| | 意味 | 具体的には |
|---|---|---|
| **A** | すぐ使える | 新しいモデル・製品・機能が「いま実際に使えるようになった」発表。その日のうちに試せるもの |
| **B** | 知っておく | 重要だが今すぐ動く必要はないもの。研究成果、方針の表明、提携・買収、規制の動き |
| **C** | 参考 | 解説・考察・まとめ・体験記など、背景を知るための記事 |

迷ったら低いほうを付けるよう指示しているので、**Aは1日に0〜2本程度**が目安です。
Aばかり付く、あるいは全くAが出ないという場合は、`summarize()` の中の基準を書き換えてください。

## カスタマイズ

**収集先を変える** … `feeds.yaml` を編集。行を足すか、`#` で消すだけです。
RSSのURLはサイト側の都合で変わることがあります。取得に失敗したものはログに `[skip]` と出るので、その行を直してください。

配信が止まった収集先はコメントアウトしてあります（2026-08-17時点で Anthropic / Microsoft / Meta の公式RSS）。
各社の発表はGoogleニュース経由で拾うようにしてありますが、公式RSSが復活したらコメントを外すほうが確実です。

**本数・時刻を変える** … `main.py` 冒頭の `PICK_COUNT`（届く本数）と、
`.github/workflows/daily.yml` の `cron` を編集します。
cronはUTC表記なので、**日本時間から9時間引いた値**を書きます（朝7時 → `0 22 * * *`）。

**要約の書き方を変える** … `main.py` の `summarize()` の中のプロンプトが指示文そのままです。ここを日本語で書き換えれば出力が変わります。

**選ぶ基準を変える** … 同じく `select()` の中のプロンプトです。日本語と英語の比率もここに書いてあります。

**日本語の記事をもっと増やす／減らす** … `main.py` 冒頭の `MIN_JA` を変えます。
これは「最低これだけは日本語を入れる」という下限で、プロンプトの比率指定とは別に
**コード側で保証**しています（AIが比率を守らない日があるため）。0にすると下限なしです。
候補に日本語の記事が1本も無い日は、本数を減らさずそのまま英語で埋めます。

## 費用の目安

Gemini API の **無料枠**で動かすことを想定しています。

このしくみが Gemini を呼ぶのは **1日2回だけ**（記事の選抜1回 + 5本まとめて和訳1回）なので、
無料枠の1日あたりリクエスト数には余裕を持って収まります。通常の使い方なら **0円**です。

ただし無料枠の条件はGoogle側の都合で変わることがあります。上限に当たると
Actionsのログに `429` が出て、しばらく待ってリトライします。恒常的に当たるようなら、
`main.py` の `PICK_COUNT` を減らすか、有料枠に切り替えてください。

**モデルを変えたいとき** … Variables に `GEMINI_MODEL` を登録すると、コードを触らずに
差し替えられます（既定は `gemini-3.5-flash`）。存在しないモデル名を入れた場合は、
実行時に使えるモデル名の一覧をログに出して停止します。

## 気をつける点

- **リポジトリはPublicを想定しています。** GitHub Pagesを無料で使うためです。
  ページに載るのは要約と用語解説だけで、原文の全文は転載していません。
  それでも公開が気になる場合は、Privateにして GitHub Pro に入る（Pagesが使えます）か、
  ページ生成をやめてLINEの通知だけにする形でも動きます。
- **Actionsの時刻は正確ではありません。** 混雑すると数分〜十数分遅れます。時報がわりには使わないでください。
- **有料記事は本文が取れません。** その場合はタイトルと抜粋から要約するので、内容は薄くなります。
- 送信済みのURLは `state.json` に記録され、同じ記事が二度届かないようになっています。
- 和訳の途中でAIの応答が壊れても、原題だけはLINEに届くようにしてあります（要約が空のまま届いたらそれです）。

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| LINEに届かない | Actionsのログに `[error] LINE送信に失敗` が出ていないか。トークンとユーザーIDの取り違えが多いです |
| カードではなく文字だけ届く | カードが弾かれたときの保険が働いています。ログに `[warn] カードで送れなかった` と、直前に LINE側のエラー内容が出ます |
| 日本語の記事が入らない | 収集先が落ちている可能性があります。ログの `[skip]` 行を確認してください。`MIN_JA` は候補に日本語があるときだけ効きます |
| ページが404 | Settings → Pages の設定が `main` / `docs` になっているか。反映に数分かかります |
| ページのデザインが崩れる | `docs/style.css` が消えていないか。相対パスで読んでいます |
| 「新着がないので終了」と出る | 36時間以内の新着がなかったか、全部送信済みです。`main.py` の `HOURS_BACK` を伸ばすと拾えます |
| `環境変数が足りません` と出て止まる | Secrets の名前が1文字でも違うと出ます。手順2の表と見比べてください |
| `モデル '...' が見つかりません` | Variables の `GEMINI_MODEL` の綴りが違います。ログに使えるモデル名が並ぶので、そこから選んでください。未設定に戻せば既定モデルに戻ります |
| ログに `429` が並ぶ | 無料枠の上限です。3回まで自動で待ち直します。毎日出るようなら有料枠への切り替えを検討してください |
| 要約が空で原題だけ届く | モデルの応答が途中で切れています。`main.py` の `summarize()` にある `max_tokens=16000` を増やすと直ることがあります |
| 記事が偏る | `feeds.yaml` から偏っている媒体を消すのが一番早いです |
